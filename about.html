How I work

I start from the operation that is already failing. At Affordable Gadgets, sales, stock, and the day’s money were being receipted by hand, on a catalogue of 200 to 500 products, and enquiries were dying in chat. RealitySync started from the boundary: a Kenya admin polygon is only useful once someone can say it is wrong, before it is used to train a model. Pulse Price started from a market price a farmer on a basic phone could not get.

The build is cut to that problem. The shop got a storefront and a role-based console on Django, Next.js, and PostgreSQL. M-Pesa STK push, callbacks, refunds, and Pesapal replaced the handwritten receipt, and a TypeScript client generated from the OpenAPI spec keeps those screens on the same API. The API runs in Docker on Google Compute Engine, with Terraform for the machines and Cloud Build to put the image there. EventFlow got the public listing and the organiser desk, shipped with Docker, GitHub Actions, Terraform, and Cloud Build, Redis beside the API. RealitySync got dbt checks that can be run again, shipped with Cloud Build, Terraform, and Docker. Pulse Price split the collector from the API, so a messy model response stays in the collector, and the price goes out over USSD.

I stay after the deploy. Prometheus scrapes the APIs and Grafana comes up with the stack. On EventFlow I watch request rate, the slow tail, and error rate. On Affordable Gadgets I watch the API, the business numbers, the funnel, the day, and the k6 tests. The shop has held above 99.9% availability, and that Compute Engine deploy brought the cloud bill down by about $300 a month.

The sites can be visited. The code behind Affordable Gadgets, FELBright, SCALE, EventFlow, the ministry, and Climate Pulse stays private. I will walk through it.
